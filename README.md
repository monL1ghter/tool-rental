# Tool Rental: сервис аренды инструментов

Backend-приложение на **Java 17 + Spring Boot**. Арендодатели выставляют инструменты (перфораторы, шуруповёрты, садовую технику), арендаторы ищут их в каталоге, бронируют на нужные даты, забирают или заказывают доставку и после возврата оставляют отзывы. Администратор следит за жалобами на отзывы.

**Какую проблему решает.** Дорогой инструмент нужен на пару дней, и покупать его невыгодно. А у владельцев такой инструмент простаивает. Сервис связывает обе стороны: считает стоимость, не даёт забронировать занятый инструмент, хранит залог и историю аренд и показывает рейтинг каждого участника.

## Технологии

- Java 17+
- Spring Boot 3.5 (Spring Web, Spring Data JPA / Hibernate, Spring Security, Validation)
- JWT (библиотека jjwt) для авторизации
- H2 (по умолчанию) или PostgreSQL
- Maven
- **Без Lombok**: геттеры и сеттеры написаны вручную, DTO сделаны на Java records

## Роли

| Роль | Что может |
|---|---|
| `RENTER` (арендатор) | искать инструменты, бронировать, продлевать и отменять аренду, писать отзывы, жаловаться на отзывы |
| `LANDLORD` (арендодатель) | всё то же + добавлять и менять свои инструменты, подтверждать брони, выдавать и принимать инструмент |
| `ADMIN` (администратор) | смотреть жалобы на отзывы, удалять любые отзывы, управлять любыми инструментами |

Арендатор может стать арендодателем запросом `POST /users/me/become-landlord`.

## Запуск

Нужны только **JDK 17+** и **Maven**. Ничего устанавливать в базу не нужно: по умолчанию используется H2 в памяти.

```bash
git clone <адрес репозитория>
cd tool-rental
mvn spring-boot:run
```

Приложение стартует на `http://localhost:8080`. При первом запуске создаются тестовые данные.

| Email | Пароль | Роль |
|---|---|---|
| `admin@toolrental.com` | `admin123` | ADMIN |
| `landlord@example.com` | `password123` | LANDLORD |
| `renter@example.com` | `password123` | RENTER |
| `renter2@example.com` | `password123` | RENTER |

Таблицы можно посмотреть в консоли H2: `http://localhost:8080/h2-console`
(JDBC URL `jdbc:h2:mem:toolrental`, пользователь `sa`, пароль пустой).
Данные в H2 хранятся в памяти и пропадают при остановке приложения.

### Запуск с PostgreSQL

1. Создайте базу:
   ```sql
   CREATE DATABASE toolrental;
   ```
2. При необходимости поменяйте логин и пароль в `src/main/resources/application-postgres.properties`
   (по умолчанию `postgres` / `postgres`, порт 5432).
3. Запустите с профилем `postgres`:
   ```bash
   mvn spring-boot:run -Dspring-boot.run.profiles=postgres
   ```

Таблицы создаются автоматически (`spring.jpa.hibernate.ddl-auto=update`).

### Настройки (`application.properties`)

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `app.jwt.secret` | тестовая строка | Секрет подписи JWT, не меньше 32 символов. **В реальном проекте замените и храните в переменной окружения** |
| `app.jwt.access-minutes` | 30 | Срок жизни access-токена |
| `app.jwt.refresh-days` | 14 | Срок жизни refresh-токена |
| `app.dev-mode` | true | Возвращать OTP-код и токен сброса пароля прямо в ответе (вместо SMS и email) |
| `app.upload-dir` | uploads | Папка для фото к отзывам |

## Как пользоваться API

Почти все методы требуют заголовок `Authorization: Bearer <accessToken>`. Токен приходит в ответе на `/auth/login`.

```bash
# 1. Вход
curl -X POST http://localhost:8080/auth/login -H "Content-Type: application/json" \
  -d '{"email":"renter@example.com","password":"password123"}'

# 2. Рейтинг пользователя (публичный метод), id арендодателя из тестовых данных: 2
curl http://localhost:8080/users/2/rating
curl http://localhost:8080/users/2/reviews

# 3. Жалоба на отзыв
curl -X POST http://localhost:8080/reviews/3/report \
  -H "Authorization: Bearer <accessToken>" -H "Content-Type: application/json" \
  -d '{"reason":"FAKE","details":"Этот человек ничего у нас не арендовал"}'
```

### Жизненный цикл аренды

```
PENDING --confirm--> CONFIRMED --start--> ACTIVE --return--> COMPLETED
   |                     |
   +------ cancel -------+--> CANCELLED
```

1. Арендатор создаёт бронь (`POST /bookings`), статус `PENDING`.
2. Арендодатель подтверждает (`/confirm`), выдаёт инструмент (`/start`) и принимает обратно (`/return`).
3. После возврата оба участника могут оставить отзыв (`POST /reviews`).

### Каталог (`/tools`)

| Метод | URL | Описание |
|---|---|---|
| GET | `/tools` | Каталог с пагинацией. Параметры: `q`, `category`, `brand`, `minPrice`, `maxPrice`, `condition`, `minRating`, `available` (по умолчанию `true`: скрытые инструменты не показываются), `sort` (`popular`, `price_asc`, `price_desc`, `new`, `rating`), `page`, `size` |
| GET | `/tools/{id}` | Карточка инструмента |
| GET | `/tools/{id}/availability?from=&to=` | Свободен ли инструмент на даты (формат `2026-12-01`) |
| GET | `/tools/{id}/reviews` | Отзывы об инструменте |
| GET | `/tools/{id}/similar` | Похожие инструменты (та же категория) |
| GET | `/tools/popular` | Популярные |
| GET | `/tools/new` | Новые поступления |
| POST | `/tools` | Добавить инструмент (арендодатель) |
| PUT | `/tools/{id}` | Изменить инструмент (владелец) |
| DELETE | `/tools/{id}` | Удалить инструмент (если по нему нет броней) |

### Бронирование (`/bookings`)

| Метод | URL | Описание |
|---|---|---|
| POST | `/bookings` | Создать бронь |
| GET | `/bookings?role=renter\|landlord&status=` | Список броней (мои аренды или брони моих инструментов) |
| GET | `/bookings/{id}` | Детали брони |
| PATCH | `/bookings/{id}` | Изменить бронь (пока она `PENDING`) |
| POST | `/bookings/{id}/confirm` | Подтвердить (арендодатель) |
| POST | `/bookings/{id}/cancel` | Отменить с расчётом возврата |
| POST | `/bookings/{id}/extend` | Продлить аренду |
| POST | `/bookings/{id}/start` | Выдать инструмент (арендодатель) |
| POST | `/bookings/{id}/return` | Принять инструмент обратно (арендодатель) |
| GET | `/bookings/{id}/price` | Стоимость брони |
| POST | `/bookings/calculate` | Предварительный расчёт без создания брони |

**Стоимость** = цена за день × число дней (оба дня включительно) + доставка (если выбрана) + залог.

**Правила возврата при отмене:**
- оплата при получении: возвращать нечего;
- арендодатель отменил или арендатор отменил до даты начала: возвращается вся сумма;
- арендатор отменил в день начала или позже: удерживается половина стоимости аренды.

### Отзывы и рейтинг

| Метод | URL | Описание |
|---|---|---|
| POST | `/reviews` | Оставить отзыв по завершённой аренде |
| GET | `/reviews?toolId=&userId=` | Список отзывов (`userId` — тот, о ком написан отзыв) |
| GET | `/reviews/{id}` | Один отзыв |
| PATCH | `/reviews/{id}` | Редактировать (автор) |
| DELETE | `/reviews/{id}` | Удалить (автор или администратор) |
| POST | `/reviews/{id}/photos` | Загрузить фото (multipart, поле `file`, JPEG/PNG, до 5 фото) |
| DELETE | `/reviews/{id}/photos/{photoId}` | Удалить фото |
| **GET** | **`/users/{id}/reviews`** | **Отзывы о пользователе** |
| **GET** | **`/users/{id}/rating`** | **Рейтинг пользователя** (средняя оценка и число отзывов) |
| **POST** | **`/reviews/{id}/report`** | **Жалоба на отзыв** (`reason`: `SPAM`, `OFFENSIVE`, `FAKE`, `OTHER`) |
| GET | `/admin/reports` | Все жалобы (администратор) |

**Как устроены отзывы.** По одной аренде каждый участник пишет не больше одного отзыва:
арендатор оценивает инструмент и арендодателя, арендодатель оценивает арендатора.
Поэтому рейтинг есть у каждого пользователя, а не только у владельцев инструментов.
Жалобу нельзя отправить на свой отзыв и нельзя отправить дважды на один и тот же.

## Структура проекта

```
src/main/java/com/toolrental
├── controller/   REST-контроллеры (принимают запрос, вызывают сервис)
├── service/      бизнес-логика
├── repository/   интерфейсы Spring Data JPA

├── security/     JWT и настройка Spring Security

```

## База данных

Основные таблицы и связи:

- `users`: пользователи (роль, email, телефон, пароль в виде BCrypt-хеша)
- `tool` → `users` (владелец): инструменты
- `booking` → `tool`, `users` (арендатор): бронирования с зафиксированными ценами
- `review` → `booking`, `users` (автор), `users` (о ком), `tool`: отзывы
- `review_photo` → `review`: фото к отзывам
- `review_report` → `review`, `users` (кто пожаловался): жалобы
- `refresh_token`, `otp_code`, `password_reset_token`: служебные таблицы для входа и восстановления пароля

## Формат ошибок

```json
{ "status": 409, "message": "Инструмент занят на выбранные даты" }
```

Коды: 400 (неверные данные), 401 (нет или неверный токен), 403 (нет прав), 404 (не найдено), 409 (конфликт, например дубль жалобы).

## Что не реализовано

В проекте есть только то, что описано в списке эндпоинтов. Не сделаны: загрузка документов для верификации, настройки уведомлений, чат, споры, привязка карт и реальная оплата, программа лояльности, промокоды. Отправка SMS и email заменена записью в лог.

**Для учебного проекта упрощено (перед реальным запуском доработать):**
- `app.dev-mode=true` отдаёт OTP-код и токен сброса пароля прямо в ответе API, на реальном сервере выключите;
- нет ограничения числа попыток ввода OTP-кода;
- вход через соцсети не проверяет токен у провайдера;
- секрет JWT и пароль БД лежат в файлах настроек, а не в переменных окружения.
